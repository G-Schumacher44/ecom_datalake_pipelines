# Validation Reports

This directory contains auto-generated validation reports that document the quality of data transformations.

## Reports

### SILVER_QUALITY.md
- **Generated by:** `src/validation/silver_quality.py`
- **Updated:** After each Silver layer transformation
- **Purpose:** Track transformation quality, pass rates, quarantine analysis
- **Commit to Git:** Yes - provides historical record of data quality

### SILVER_PROFILE.md
- **Generated by:** `src/validation/silver_quality.py` (when `SILVER_PROFILE_ENABLED=true`)
- **Updated:** With Silver validation when profiling is enabled
- **Purpose:** Lightweight schema profile (row count, columns, dtypes, nulls)
- **Commit to Git:** Optional - useful for snapshotting schema health

### BRONZE_QUALITY.md
- **Generated by:** `src/validation/bronze_quality.py`
- **Updated:** Before Silver layer transformation
- **Purpose:** Track manifest coverage, row counts, empty partitions
- **Commit to Git:** Yes - provides historical record of data quality

### ENRICHED_QUALITY.md
- **Generated by:** `src/validation/enriched_quality.py`
- **Updated:** After Enriched Silver transformations
- **Purpose:** Validate partitioned outputs (business date or ingest_dt), minimum row counts, schema snapshot, null rates, and sanity checks
- **Commit to Git:** Yes - documents Enriched Silver health

### Future Reports

- `BRONZE_METADATA.md` - Bronze layer metadata validation
- `BRONZE_QUALITY.md` - Bronze Pydantic validation results
- `LATEST_RUN.md` - Quick summary of most recent pipeline run

## Why Self-Documenting Reports?

1. **Version Control** - Git history shows quality trends over time
2. **Team Visibility** - Non-engineers can read Markdown reports
3. **PR Reviews** - Code reviewers can see data quality impact
4. **Debugging** - Historical record helps diagnose issues
5. **Compliance** - Auditable trail in version control

## Usage

These reports are auto-generated - **DO NOT EDIT MANUALLY**.

### Run Checks (dbt + pytest)

```bash
# Base Silver models + tests
dbt build --project-dir dbt_duckdb --profiles-dir dbt_duckdb --select "base_silver.*"

# Unit tests for transforms/validation helpers
pytest -q
```

### View Latest Report

```bash
cat docs/validation_reports/SILVER_QUALITY.md
```

### Track Quality Over Time

```bash
# See quality changes in Git history
git log -p docs/validation_reports/SILVER_QUALITY.md

# Compare quality between commits
git diff HEAD~1 docs/validation_reports/SILVER_QUALITY.md
```

### Generate Report Manually

```bash
# After running dbt (soft mode: local/dev defaults)
python src/validation/silver_quality.py \
  --bronze-path samples/bronze \
  --silver-path data/silver/base \
  --quarantine-path data/silver/base/quarantine \
  --output-report docs/validation_reports/SILVER_QUALITY.md

# Or use env/config defaults
BRONZE_BASE_PATH=samples/bronze \
SILVER_BASE_PATH=data/silver/base \
SILVER_QUARANTINE_PATH=data/silver/base/quarantine \
python src/validation/silver_quality.py

# Optional: enable Silver profiling
SILVER_PROFILE_ENABLED=true python src/validation/silver_quality.py \
  --bronze-path samples/bronze \
  --silver-path data/silver/base \
  --quarantine-path data/silver/base/quarantine \
  --output-report docs/validation_reports/SILVER_QUALITY.md

# Strict mode (enforces FK checks regardless of environment)
STRICT_FK=true python src/validation/silver_quality.py \
  --bronze-path samples/bronze \
  --silver-path data/silver/base \
  --quarantine-path data/silver/base/quarantine \
  --output-report docs/validation_reports/SILVER_QUALITY_strict.md

# Bronze quality (local or GCS)
python src/validation/bronze_quality.py \
  --bronze-path samples/bronze \
  --output-report docs/validation_reports/BRONZE_QUALITY.md

# Enriched quality
python src/validation/enriched_quality.py \
  --enriched-path data/silver/enriched \
  --ingest-dt 2026-01-12 \
  --output-report docs/validation_reports/ENRICHED_QUALITY.md
```

## Report Format

All reports follow a consistent structure:

1. **Summary** - High-level status and metrics table
2. **Issues Detected** - Detailed analysis of failures/warnings
3. **Deep Dive** - Per-table analysis and recommendations
4. **Metadata** - Report generation details

## Integration with Observability

Each report generation also writes:
- JSON metrics to `data/metrics/{metric_type}/`
- Structured logs to `data/logs/audit/`

This dual-output strategy provides:
- **Human-readable** reports (Markdown)
- **Machine-readable** metrics (JSON for analytics)
